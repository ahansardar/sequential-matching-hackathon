# Suggested reply to the organisers

**Subject:** LuminaX - corrected Round 1 addendum and reconsideration request

Dear Vasudha,

Thank you for offering to review a corrected addendum. We repeated the analysis
and implemented each part of your feedback:

- every comparison now keeps all six variants of a generated seed together and
  resamples whole seed groups with equal variant weighting;
- the history gain remains uncertain under the corrected interval, so we have
  retracted it as a proven improvement;
- the two directional targets are explicitly defined as recorded Yes by the
  response deadline, with disjoint fit, calibration and untouched holdout seed
  blocks, mature outcomes and time-band calibration checks;
- profile-completeness analysis now includes coverage, unserved rate, waiting,
  repeated service, completed outcomes, opportunity exposure and paired 50%
  and 100% masking tests;
- guarded cardinality is evaluated on completed outcomes and is not retained;
- the submitted clarification rule is invariant to equivalent input ordering;
  and
- an independent validator, permanent seed ledger and fixed 33-item closure
  register make the evidence package rerunnable.

The corrected analysis rejects several attractive but unsupported ideas. We
see that as the value of the work, not the end of it: the selected Round 1
runtime is a conservative, fail-closed foundation that protects reciprocal
constraints and removes state-order dependence. It is starter-compatible in
its compatibility ranking, but adds deterministic clarification, malformed-
input safeguards and a reproducible promotion process.

For Round 2 we would test three focused challengers without using hidden
simulator truth: learn non-uniform compatibility weights only from matured
observable outcomes on disjoint seed blocks; allocate clarification budget by
the expected observable feasibility unlocked per unit cost; and add time-band
drift monitoring with subgroup calibration gates. None would enter the runtime
unless it improves fresh matched-seed MSMI while preserving feasibility,
service and runtime guardrails.
